Section 1

Normative Core Protocol: pinUvAuthProtocol = 4 with HPKE Export-Only (aead_id = 0xFFFF)

1.1 Why RFC 9180 HPKE Export-Only (aead_id = 0xFFFF) Maximizes Protocol 2 Firmware & Hardware Reuse

1. 100% Reuse of Protocol 2's encrypt(), decrypt(), authenticate(), & verify()

Exports a 64-byte sharedSecret = K_HMAC (32B) || K_AES (32B) via RFC 9180 Context.Export. Existing Secure Elements with hardware AES-256-CBC and HMAC-SHA-256 require 0 bytes of AES-GCM code and no sequence-counter state!

2. Post-Quantum & Hybrid KEM Agility (0x2A: pinUvAuthKems)

Supports X-Wing (0x647a, MTI default), MLKEM768-P256 (0x0050, hardware SE default), ML-KEM-768 (0x0041), and ML-KEM-1024 (0x0042).

3. Authenticated 0x0A UV Requests via HMAC-SHA-256

Closes CTAP 2.3's unauthenticated getPinUvAuthTokenUsingUvWithPermissions (0x0A) gap by requiring 0x04: pinUvAuthParam = HMAC-SHA-256(K_HMAC, PinUvAuthTranscript_v4).

4. Authenticated Responses (0x02: pinToken) via HMAC-SHA-256

Eliminates unauthenticated AES-256-CBC malleability on pinToken (0x02) by returning 0x04: pinUvAuthParam = HMAC-SHA-256(K_HMAC, Transcript || pinToken) alongside 0x02.

Section 2

Multi-Tier Trust Hierarchy, Pairing PINs, Unattested PQ-PAKE, Dual Modes & NFC Recovery

2.1 Tier 1: Enterprise Mutually Authenticated Key Agreement (Host Auth)

Scoped to authenticators with pk_batch and aaguid. Provisioned via authenticatorConfig (0x0D, subCmd 0x06: setEnterpriseHostTrustAnchors), advertised via options.enterpriseHostAuth and 0x2C: pinUvAuthHostAlgs, and enforced at getKeyAgreement (0x02) with immediate CTAP2_ERR_HOST_UNAUTHENTICATED (0x3E) rejection if 0x09: HostAuthPayload is invalid.

2.2 Tier 2: Batch Key Pinning & Same-Batch Evil-Twin Detection

Personal platforms pin (deviceIdentifier, PPUAT_v4, kemId, pk_batch, VerifiedGetInfoProfile) for 0-RTT MITM immunity, require mandatory PPUAT revocation if pk_batch rotates, and trigger a mandatory "New / Unrecognized Authenticator Detected" UI warning if an attacker supplies a different device from the exact same batch (detected via encIdentifier 0x19 mismatch).

2.3 Initial Setup & Reset: Temporary / 6-Digit Factory Pairing PIN (forcePINChange = true)

Devices ship with an IT Temporary PIN or random 6-digit scratch-off Factory Pairing PIN and forcePINChange: true, using changePIN (0x04) over the PIN-blinded PQ-PAKE to prevent initial-setup MITM. Executing authenticatorReset (0x07) restores the factory-immutable Pairing PIN and resets pinRetries = 8.

2.4 Tier 3: Unattested (aaguid = 016) ML-KEM PQ-PAKE & 8-Try pinRetries

Blinds t_blinded = (t_eph + m_w) mod 3329 in getKeyAgreement (0x02) and uses HPKE.SetupPSKS(..., psk = w, aead_id = 0xFFFF) with the 4-rule write-before-verify pinRetries state machine (≤ 8 tries total, ≤ 3 per boot, single-use dk_eph, constant-time FO implicit rejection).

2.5 Dual Post-Pairing Modes (Mode A Asymmetric Pinning vs. Mode B Symmetric PPUAT_v4) & 2.6 Stateless 0-RTT NFC Recovery
  • Mode A (Asymmetric Pinning) & Mode B1 (Symmetric 256-Bit PPUAT_v4 with 32B clientNonce): Both run RFC 9180 KeySchedulePSK (aead_id = 0xFFFF) in 0-RTT to export (K_HMAC, K_AES), verifying HMAC-SHA-256(K_HMAC, ...) before touching pinRetries.
  • NFC Cached-PIN Silent Recovery (0x09): When an NFC field drop wipes the volatile PUAT, the Client uses its RAM-cached PIN and PPUAT_v4 (Mode B1 32B clientNonce or Mode A pk_batch) to send a 0-RTT 0x09 without re-prompting the user or calling GetInfo (0x04) / getKeyAgreement (0x02). If NFC dropped between 0x02 and 0x09 on an unbound host, 0x09 returns CTAP2_ERR_KEY_AGREEMENT_EXPIRED (0x3F) with 0 pinRetries lost.
  • NFC On-Device UV Recovery (0x0A): While the hardware sensor must re-verify the finger on re-tap (unless brief retention SRAM is used), Protocol 4 skips GetInfo (0x04) and getKeyAgreement (0x02) completely and jumps directly to 0-RTT 0x0A!

class HPKEExportOnlyProtocol4Context:
    """RFC 9180 HPKE Export-Only (kdf_id = 0x0001, aead_id = 0xFFFF) for pinUvAuthProtocol = 4."""
    def __init__(self, exporter_secret: bytes):
        suite_id = b"HPKE\x64\x7a\x00\x01\xff\xff"
        self.k_hmac = hkdf_expand(exporter_secret, suite_id + b"sec" + b"CTAP2 HMAC key", 32)
        self.k_aes  = hkdf_expand(exporter_secret, suite_id + b"sec" + b"CTAP2 AES key", 32)

    def encrypt(self, pt: bytes) -> bytes:
        iv = os.urandom(16)
        return iv + Cipher(algorithms.AES(self.k_aes), modes.CBC(iv)).encryptor().update(pt)

    def authenticate(self, msg: bytes) -> bytes:
        return hmac.new(self.k_hmac, msg, "sha256").digest()
