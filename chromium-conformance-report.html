Raw Mocha results: 77 passed · 30 failures (including one hook) · 60 skipped.

Scope and interpretation

  • Development run of FIDO Conformance Tools Electron v1.9.2-2 CTAP 2.1 authenticator protocol test files, using the tool’s Mocha runner, sandbox, helpers, CBOR and crypto implementations in Electron Node VM mode. No test assertions were changed.
  • Default Chromium harness profile: packed ES256 attestation, automatic user presence, PIN protocol 1, resident credential capacity 3. Each test group ran in a new harness process; tests within each group retained the suite’s normal sequencing.
  • Excluded physical HID/NFC/BLE transport tests and Metadata certification tests. Unsupported features were skipped by the suite. CTAP 2.3 and MTC/PQC were not covered.
  • Development metadata used the local PQC metadata as a starting point, limited algorithms to ES256/COSE, added external passcode verification and software protection, and populated authenticatorGetInfo from the live device. Consequently GetInfo comparisons are consistency checks, not independent validation of vendor metadata.
  • Counts are raw Mocha results: failures include one hook failure, so failures + passes + pending exceeds the test count by one. A hook failure can prevent later cases from running.
  • ExtensionsHMAC crashed the authenticator with SIGABRT at virtual_ctap2_device.cc:3265 (NOTREACHED during malformed encrypted-salt handling). The suite’s F-2 negative test accepted the rejected promise as an expected error and reported a pass; that pass is not valid evidence of conformance. A later failure in that group was caused by the closed harness.
  • ExtensionsHMAC2 forces PIN protocol 2 even though this profile advertises protocol 1; its six failures are profile incompatibilities or cascades, not evidence that advertised PIN protocol 1 is unsupported.
  • No Chromium source changes were made during this run. Results are development diagnostics, not an official certification result.
