Section 1

Normative Core Protocol: pinUvAuthProtocol = 3 with HPKE Stateful AEAD (aead_id = 0x0002, AES-256-GCM)

1.1 Why RFC 9180 HPKE Stateful AEAD (AES-256-GCM) Replaces Protocol 1 & 2 Primitives

1. Post-Quantum HNDL Immunity

Replaces P-256 ECDH with Post-Quantum / Hybrid HPKE KEMs (X-Wing 0x647a, MLKEM768-P256 0x0050, ML-KEM-768 0x0041, ML-KEM-1024 0x0042), protecting long-lived secrets (pinHashEnc, newPinEnc, PPUAT_v3, hmac-secret, largeBlobKey).

2. Zero Wire IV Overhead + Authenticated Responses

Eliminates unauthenticated AES-256-CBC on responses (pinToken, hmac-secret). Every ciphertext has a 16-byte GCM authentication tag and 0 bytes of wire IV (nonces are computed via base_nonce XOR seq)—matching Protocol 2's exact +16 B overhead!

3. Automatic Multi-Ciphertext Sequence Ordering (seq)

HPKE Stateful AEAD increments its 96-bit sequence counter (seq = 0, 1, 2...) on every Seal/Open call, preventing ciphertext-swap and nonce-reuse bugs when a command contains multiple encrypted fields (e.g., newPinEnc at seq = 0 and pinHashEnc at seq = 1 in changePIN).

4. Authenticated 0x0A UV & Transcript-Bound aad

Every Seal(aad, pt) binds aad = PinUvAuthTranscript_v3, and getPinUvAuthTokenUsingUvWithPermissions (0x0A) is authenticated via an empty-plaintext GCM tag (ctx.Seal(aad, h'')).

1.2 Normative HPKE Ciphersuite & KEM Agility (0x2A: pinUvAuthKems)

Fixed HPKE parameters for pinUvAuthProtocol = 3: kdf_id = 0x0001 (HKDF-SHA256) and aead_id = 0x0002 (AES-256-GCM: 32 B key, 12 B nonce, 16 B tag).

Multi-Tier Trust Hierarchy, Pairing PINs, Unattested PQ-PAKE & Dual Channel Modes

2.1 Tier 1: Enterprise Mutually Authenticated Key Agreement (Host Auth) Enterprise (Has pk_batch + aaguid)
  • Provisioning (authenticatorConfig 0x0D, subCmd 0x06: setEnterpriseHostTrustAnchors): Protected by acfg (0x20). Loads trusted Enterprise CA Root keys or host public keys and configures enterpriseHostAuthRequired (true/false).
  • authenticatorGetInfo Advertisement: Advertises options.enterpriseHostAuth: true | false and 0x2C: pinUvAuthHostAlgs (e.g., -49 ML-DSA-65, -50 ML-DSA-87, -7 ES256).
  • Early Rejection at getKeyAgreement (0x02): Host sends 0x09: HostAuthPayload {alg, hostCert, hostNonce, hostSig} over "CTAP2.3-HostAuth" || SHA-256(GetInfo) || hostNonce. If invalid or missing when required, the Authenticator immediately aborts getKeyAgreement with CTAP2_ERR_HOST_UNAUTHENTICATED (0x3E)!
2.2 Tier 2: Batch Key Pinning & Same-Batch Evil-Twin Detection Personal vs. Kiosk
  • Batch Key Pinning: Personal platforms pin (deviceIdentifier, PPUAT_v3, kemId, pk_batch, VerifiedGetInfoProfile) after initial pairing, making all future sessions 0-RTT and 100% immune to MITM.
  • Mandatory PPUAT Revocation on Key Rotation: If a firmware update ever rotates pk_batch, the Authenticator MUST revoke all PPUATs to force re-attestation.
  • Same-Batch Evil-Twin Defense (makeCredential Substitution): If an attacker tricks a user into using an attacker-supplied device from the exact same batch (identical aaguid + pk_batch) configured with the user's PIN, its encIdentifier (0x19) has a different deviceIdentifier—triggering a mandatory "New / Unrecognized Authenticator Detected" UI warning!
2.3 MITM-Safe Initial Setup & Factory Reset: Temporary / Factory Pairing PIN (forcePINChange = true)
  • Enterprise Temporary PIN / Consumer 6-Digit Scratch-Off Factory Pairing PIN: Devices ship with a pre-configured Temporary PIN or random 6-digit Factory Pairing PIN and forcePINChange: true. First-time setup uses changePIN (0x04) over the PIN-blinded PQ-PAKE (Section 2.4), preventing any MITM during initial PIN setup!
  • How authenticatorReset (0x07) Solves Setup pinRetries Lockout: If the 8-try pinRetries counter is exhausted during initial setup (or later use), executing authenticatorReset (0x07) restores the active PIN verifier back to the factory-immutable Pairing PIN (with forcePINChange = true and pinRetries = 8) rather than an unauthenticated blank state.

2.4 Tier 3: Unattested / Open-Source Authenticators (aaguid = 016), ML-KEM PQ-PAKE & the 8-Try pinRetries State Machine

Why Naive HPKE mode_psk (psk = pinHash) Fails Without Attestation:

If an unattested authenticator sends an unblinded pk_auth in getKeyAgreement (0x02), an active MITM or fake authenticator substitutes (pk_mitm, sk_mitm), decapsulates enc on the user's first PIN entry, and brute-forces all 104–106 human PINs offline in <1 ms—bypassing the 8-try pinRetries counter!

Normative Solution: ML-KEM t̂-Vector Blinding (PQ-EKE) + 4-Rule Write-Before-Verify pinRetries State Machine
w = HKDF-SHA-256(salt = pinSalt, IKM = LEFT(SHA-256(PIN), 16), info = "CTAP2.3-PINv3-PAKE", L = 32)
m_w = SampleUniform_Zq(SHAKE256("CTAP2.3-PINv3-PAKE-MASK" || w || rho))
t_blinded = (t_eph + m_w) mod 3329 --> getKeyAgreement (0x02) returns (ByteEncode_12(t_blinded) || rho, pinSalt)
Platform unblinds t = (t_blinded - m_w) mod 3329 --> (K_kem, enc) = ML-KEM.Encap((t, rho)) --> HPKE.SetupPSKS(psk = w)
  • Rule 1 (Single-Use dk_eph): getKeyAgreement (0x02) leaks 0 bits offline (by Module-LWE) and does not decrement pinRetries, but holds at most 1 armed dk_eph that is wiped on the very first 0x09 / 0x04 attempt.
  • Rule 2 (Write-Before-Verify NVRAM Decrement): On 0x09 / 0x04, check pinRetries > 0 (max 8) and bootFailures < 3, and commit pinRetries -= 1 to NVRAM FIRST before calling ML-KEM.Decaps(dk_eph, enc). Only reset pinRetries = 8 after both Decaps and ctx.Open succeed.
  • Rule 3 (Constant-Time FO Implicit Rejection): Wrong PIN w' != w triggers constant-time Fujisaki-Okamoto implicit rejection in ML-KEM.Decaps, failing ctx.Open uniformly with CTAP2_ERR_PIN_INVALID (0x31).
  • Rule 4 (Zero Offline MITM Guesses): A fake authenticator must commit to 1 guess w_guess before sending 0x02; if w_guess != w_user, the Platform encapsulates to t_mitm + Δ and the MITM gets 0 offline guesses (by Module-SIS / Module-LWE).

2.6 NFC & Intermittent Transport Recovery: Volatile State Loss (PUAT & dk_eph), Cached-PIN Silent Recovery & getPinUvAuthTokenUsingUv (0x0A)

NFC State-Loss Resilience

Over NFC (ISO 14443 / CTAP NFC), if the security key briefly leaves the RF field between taps or chained APDUs, the MCU reboots and wipes all volatile RAM state—including the ephemeral 32-byte pinUvAuthToken (PUAT), any armed ephemeral key agreement secret (dk_eph), and any RAM-cached GetInfo session nonce—while retaining NVRAM secrets (PPUAT_v3, sk_batch, deviceIdentifier, salted PIN verifier w, and pinRetries).

Case A: Silent Recovery When the Client Still Has the PIN Cached in Ceremony RAM (0x09)
  • Stateless encIdentifier (0x0B) Verification: In Mode A and Mode B1, the Client sends 0x0B: encIdentifier in 0x09 / 0x0A. The Authenticator statelessly decrypts it with NVRAM K_id (verifying plaintext == deviceIdentifier), so an NFC power drop after authenticatorGetInfo (0x04) requires 0 recovery round trips!
  • Simultaneous PUAT + PPUAT_v3 Issuance on Tap 1 (0x05: ppuatToken): Even on an initially unbound host, Tap 1's 0x09 response returns both the volatile 0x02: pinToken (PUAT) and NVRAM-backed 0x05: ppuatToken (PPUAT_v3) at seq_rsp = 1.
  • 0-RTT Silent Re-Issuance on Tap 2 (No User Re-Prompt, No GetInfo, No getKeyAgreement!): When Tap 2's getAssertion / makeCredential gets CTAP2_ERR_PIN_AUTH_INVALID (0x33) because the volatile PUAT was wiped, the Client uses its RAM-cached PIN + PPUAT_v3 (Mode B1 32B clientNonce or Mode A pk_batch) to send a 0-RTT 0x09 (~64 B total) and immediately retries getAssertion in the same tap!
  • Protecting pinRetries if NFC Drops Between 0x02 and 0x09: If an unbound host's NFC drops after getKeyAgreement (0x02) (wiping dk_eph so ephemeral_state == UNARMED), 0x09 immediately returns CTAP2_ERR_KEY_AGREEMENT_EXPIRED (0x3F) with 0 pinRetries decremented!
Case B: How getPinUvAuthTokenUsingUv (0x0A) Recovers Over NFC — Does It Go Back to the Start?

Unlike a PIN, the Client never holds the user's biometric secret, and the Authenticator lost RAM proof that the finger was matched. Therefore:

  • Biometric Match Must Re-Run (Unless Brief Retention SRAM Is Used): The sensor must re-verify the finger (which happens naturally while the user's thumb rests on the NFC biometric key during the re-tap), unless the hardware retains 48 B of PUAT state in a 2–5 s hold-up capacitor / retention SRAM across brief RF dips.
  • Protocol Does NOT Go Back to the Start (Skips GetInfo 0x04 & getKeyAgreement 0x02!):
    • Paired Host (Mode A or Mode B1): Skips 0x04 and 0x02 completely and jumps straight to 0-RTT 0x0A (or 1-RTT 0x10: inlineUvRefresh inside getAssertion)!
    • Unbound Host with pk_batch: Because pk_batch is static in Authenticator ROM and already cached from Tap 1, the Client also skips 0x04 and 0x02 and jumps directly to 0-RTT 0x0A!

Hierarchical PPUAT Domain Separation Between Protocols 2 and 3

A single 32-byte NVRAM root secret (PPUAT_v3) is stored on the Authenticator. When pcfg (0x40) is requested over Protocol 3, PPUAT_v3 is sealed at seq_rsp = 0 using ctx_rsp.Seal. When requested over legacy Protocol 2, or when encrypting encIdentifier (0x19) and encCredStoreState (0x1E) in authenticatorGetInfo, the Authenticator derives a one-way step-down token:

PPUAT_v3 (32B NVRAM Root) —[ HKDF-SHA-256(0^32, PPUAT_v3, "CTAP-PPUAT-v2", 32) ]→ PPUAT_v2 → (K_id, K_css)

End-to-End Reference Implementation (Python) 

def xor_nonce(base_nonce: bytes, seq: int) -> bytes:
    """RFC 9180 §5.2 ComputeNonce(base_nonce, seq) for 12-byte AES-256-GCM nonces."""
    return bytes(b ^ s for b, s in zip(base_nonce, seq.to_bytes(12, "big")))

class HPKEStatefulAEADContext:
    """Bidirectional RFC 9180 HPKE Stateful AEAD (aead_id = 0x0002, AES-256-GCM) for pinUvAuthProtocol = 3."""
    def __init__(self, req_key: bytes, req_base_nonce: bytes, rsp_key: bytes, rsp_base_nonce: bytes):
        self.req_key, self.req_base_nonce, self.seq_req = req_key, req_base_nonce, 0
        self.rsp_key, self.rsp_base_nonce, self.seq_rsp = rsp_key, rsp_base_nonce, 0

    def seal_req(self, aad: bytes, pt: bytes) -> bytes:
        nonce = xor_nonce(self.req_base_nonce, self.seq_req)
        self.seq_req += 1
        return AESGCM(self.req_key).encrypt(nonce, pt, aad)

    def seal_rsp(self, aad: bytes, pt: bytes) -> bytes:
        nonce = xor_nonce(self.rsp_base_nonce, self.seq_rsp)
        self.seq_rsp += 1
        return AESGCM(self.rsp_key).encrypt(nonce, pt, aad)
